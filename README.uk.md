# Bookify

[English](README.md) | **Українська**

Застосунок для запису на послуги на кшталт Booksy.

## Поточні можливості

- Гість вибирає послугу, призначеного спеціаліста й вільний час, а потім
  надсилає заявку на бронювання зі своїм ім’ям і номером телефону.
- Доступність враховує тижневий графік спеціаліста в часовому поясі бізнесу
  та наявні записи. PostgreSQL запобігає перетину активних бронювань одного
  спеціаліста навіть за одночасних запитів.
- У захищеній панелі `/business` працівники можуть підтверджувати й відхиляти
  заявки, скасовувати підтверджені бронювання, редагувати тижневі години
  роботи спеціалістів, створювати та редагувати послуги. Під час створення
  або редагування послуги працівник обирає спеціалістів, які її надають.

## Структура проєкту

- `frontend/` — сторінка бронювання й панель бізнесу на Next.js і React. Див. [документацію фронтенду](frontend/README.md).
- `backend/` — API на Express і TypeScript. Див. [документацію бекенду](backend/README.md).
- `compose.yaml` — конфігурація локального середовища PostgreSQL.

PostgreSQL працює в Docker. Фронтенд і бекенд запускаються безпосередньо
на комп’ютері. Бекенд підключається до PostgreSQL через Prisma Client зі
спільним пулом з’єднань `pg`. Перед прийманням HTTP-запитів бекенд перевіряє
з’єднання, а під час штатного завершення роботи закриває пул.

## Вимоги

- Node.js 24 або новішої версії та pnpm для запуску застосунків.
- Docker Desktop із запущеним рушієм Linux-контейнерів і Docker Compose.

## Запуск бази даних

Виконуй команди з кореня репозиторію. Під час першого налаштування створи
локальний файл конфігурації в PowerShell:

```powershell
Copy-Item .env.example .env
```

Якщо `.env` уже існує, відредагуй потрібні значення в ньому. Пароль із прикладу
призначений лише для локальної розробки. Git ігнорує локальний файл `.env`.

```sh
docker compose config --quiet
docker compose up -d --wait postgres
docker compose ps
```

Під час першого запуску Docker завантажує офіційний образ `postgres:18` та
ініціалізує базу. Параметр `--wait` чекає на успішну перевірку готовності.
Порт відкрито на `127.0.0.1`, тому база доступна лише з цього комп’ютера.

Параметри підключення за замовчуванням:

| Параметр | Значення |
| --- | --- |
| Хост | `127.0.0.1` |
| Порт | `5432` (або `POSTGRES_PORT` із `.env`) |
| База даних | `bookify` (або `POSTGRES_DB`) |
| Користувач | `bookify` (або `POSTGRES_USER`) |
| Пароль | `POSTGRES_PASSWORD` із локального `.env` |

Ці налаштування призначені для локальної розробки. Образ створює початкового
користувача з адміністративними правами. У робочому середовищі застосунок має
використовувати окрему роль лише з необхідними правами.

## Перевірка бази даних

Виконай SQL-запит за допомогою клієнта `psql`, який уже є в контейнері:

```sh
docker compose exec postgres psql -U bookify -d bookify -c 'SELECT current_database(), current_user, 1 AS connection_check;'
```

Щоб відкрити інтерактивний сеанс SQL, виконай:

```sh
docker compose exec postgres psql -U bookify -d bookify
```

У цих командах використано стандартні назви бази та користувача. Якщо ти змінив
їх у `.env`, підстав відповідні значення в параметри `-U` та `-d`. Команда
`\q` закриває `psql`. Щоб перевірити готовність бази й переглянути журнали,
виконай:

```sh
docker compose ps
docker compose logs --tail=50 postgres
```

Перевірка готовності використовує `pg_isready`, щоб визначити, чи приймає
PostgreSQL з’єднання. Перевірка таблиць застосунку й входу за паролем до неї
не входить. Наведені SQL-команди виконуються всередині контейнера через
локальний сокет. Підключення з комп’ютера використовують TCP і пароль.

## Контейнери та збереження даних

Образ містить програмне забезпечення PostgreSQL, а контейнер є його запущеним
екземпляром. Іменований том `postgres_data` зберігає файли бази окремо від
контейнера. Для PostgreSQL 18 том під’єднується до `/var/lib/postgresql`.

```sh
docker compose stop postgres
docker compose start postgres
```

Щоб видалити контейнери й мережу проєкту та зберегти дані бази, виконай:

```sh
docker compose down
```

Команда `docker compose up -d --wait postgres` створить контейнер знову з тими
самими даними. Команда `docker compose down --volumes` видаляє також том із
базою та всі його дані. Для звичайної зупинки використовуй `docker compose down`.

Образ використовує `POSTGRES_DB`, `POSTGRES_USER` і `POSTGRES_PASSWORD` лише
для ініціалізації порожнього каталогу даних. Зміни в `.env` після ініціалізації
не перейменовують наявну базу, не змінюють її ролі й не скидають пароль.

## Файли змінних середовища

- Кореневий `.env` — конфігурація, яку читає Docker Compose.
- `backend/.env` — конфігурація, яку завантажує команда запуску бекенду для розробки.
- `frontend/.env.local` — необов’язкова серверна конфігурація Next.js.

Кожен із цих файлів читає свій процес. Compose використовує кореневий `.env`
для підстановки змінних. Секція `environment` у конфігурації сервісу визначає,
які значення потраплять у контейнер. Процес Node.js на комп’ютері їх звідти
не отримує. Налаштуй `DATABASE_URL` у `backend/.env` відповідно до параметрів
бази в кореневому `.env`. Формат рядка підключення описано в
[налаштуванні бекенду](backend/README.md). Для доступу до панелі вкажи той
самий ID керованого бізнесу й токен API в обох застосунках. У конфігурації
фронтенду задай окремий пароль для входу. Див. [налаштування панелі](frontend/README.md#business-dashboard).

## Застосування схеми бази даних

Налаштуй `backend/.env`, встанови залежності бекенду й виконай:

```sh
pnpm -C backend db:migrate
```

Prisma Migrate застосовує нові міграції для бізнесів, послуг, спеціалістів,
їхніх призначень, тижневих робочих інтервалів і бронювань. Команда записує
історію в `_prisma_migrations` і пропускає вже застосовані міграції.
Запускай її окремо перед запуском API. Схему й порядок внесення наступних
змін описано в
[документації міграцій](backend/prisma/migrations/README.md).

Після встановлення залежностей бекенду виконай `pnpm -C backend db:generate`.
Для наявних баз, створених попереднім інструментом виконання SQL, перед
застосуванням міграцій Prisma потрібно виконати описану в документації
процедуру фіксації початкового стану.

За потреби заповни базу розробки демоданими командою `pnpm -C backend db:seed`.
Демо містить один бізнес, три послуги й двох спеціалістів із робочими годинами
в будні. Ідентифікатори записів і поведінку повторного запуску описано в
[документації демоданих](backend/README.md#demonstration-data).

## Запуск застосунків

Після запуску PostgreSQL, встановлення залежностей обох застосунків і
налаштування бази виконай ці команди в окремих терміналах:

```sh
pnpm -C backend dev
pnpm -C frontend dev
```

- [Публічна сторінка бронювання](http://localhost:3000/)
- [Панель бізнесу](http://localhost:3000/business)
- [Перевірка готовності бекенду](http://localhost:4000/api/health)
